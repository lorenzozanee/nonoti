# nonoti v0.1.0 Implementation Plan

## Phase 1: Technical Spike

1. Scaffold one Android app module for Android 13+, Compose, Kotlin, Hilt, Room, DataStore, Navigation, and test tooling. Preserve the existing launcher art and exclude app data from backups.
2. Add failing unit tests for circular Focus Block validation, cross-midnight calculation, Start now, continuous-session merging, and deterministic DST handling; implement the domain model to pass them.
3. Add failing unit tests for Focus state reconciliation, readiness failure, idempotent boundary transitions, and release timeout; implement the coordinator against fake platform ports.
4. Add failing unit and Room tests for notification eligibility, key-based upsert, update/cancel behavior, group handling, and distinct counts; implement storage and policy.
5. Add Android implementations for readiness checks, app-owned Automatic Zen Rule, exact alarms, notification listener, boot/time/package receivers, recovery, quiet release, and summary notification.
6. Add the minimal readiness, one-shot Focus, locked Box, compatibility self-test, and recovery UI needed to exercise the Spike end to end.
7. Run unit, lint, and instrumented tests. Exercise the Spike on API 33, 34, 35, and 37 Google API emulators. Record machine-verifiable results separately from human sensory observations.

## Phase 2: Product UI and remaining behavior

1. Add recurring Focus Block persistence and complete Focus UI using tested domain behavior.
2. Add full Box aggregation, retention, app icons, source-app opening, clear behavior, and privacy protections.
3. Add Settings for readiness, call/alarm policy, allowed apps, Emergency Access, retention, privacy, and compatibility state.
4. Add the static shortcut and foreground-only Emergency Access lease with all relock triggers.
5. Add adaptive navigation, large-text, dark-theme, TalkBack, state-restoration, and window-size tests.
6. Run the complete automated emulator matrix and guided manual compatibility journeys.

## Release gate

Do not mark the goal complete or claim universal compatibility until the product-spec acceptance criteria pass on every declared supported emulator and at least one real Android 13+ OEM device. When real hardware is unavailable, ship only a build whose in-app compatibility gate blocks unverified devices and report the missing hardware evidence explicitly.
